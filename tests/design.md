# 統合テストの設計と対応表（ゆびあそび）

使い方は [README.md](README.md)。ここには「何を・なぜ・どこで確かめているか」をまとめる。
（元は一時フォルダの testsuite/design.md・inventory.md。2026-10 に tests/ へ移し、効果音・タッチ操作・スコア欄の桁数の確認を取り込んだ）

## 1. 経緯（棚卸しの要点）

- 以前は修正のたびに一時フォルダへ確認用スクリプトを作っていた。棚卸しの時点で 35 本・判定 563 項目＋観察のみ約 900、全部流すと約 15 分（判定つきの回帰テストだけで 5.5 分）。
- 問題点：画面サイズの総当たりが時間の大半／キャッシュ版数（v4〜v6）の決め打ちで SW を更新するたびに 3〜4 本の期待値を書き換え／環境依存・不安定な判定 2 件／作業ツリーやリポジトリに書き込むスクリプト／観察のみで合否が出ない（十字キー 43px を見ていたのに誰も不合格にしなかった）／Safari の低い横持ち × ブロックを判定つきで見ていなかった（→ K1）。
- これを 1 つのスイートにまとめ、同値分割・境界値・ペアワイズ・リスクで項目を絞った（563 → full 約 200、smoke 約 80）。

## 2. 方針

```
              V  画面サイズ：代表・境界の両側・ペアワイズ 12 行だけ        full（smoke は最も狭い・最も低い画面）
          D/E/S/P/A/T  ブラウザの機能テスト：端末は iPhone 13 の 1 種類    リスクの高いものは smoke
      L/A1  Node：2048・キリトリのロジック・sw.js/manifest/HTML の静的検査（0 秒）   すべて smoke
```

- **L（Node）**：`games/2048/index.html`・`games/kiritori/index.html` の script を vm で実行し、公開 API `window.Tile2048Logic`・`window.KiritoriLogic` を直接呼ぶ。sw.js・manifest・各 HTML・メニューの GAMES は文字列として検査。
- **機能テスト**は端末を iPhone 13 に固定（操作の結果は画面サイズに依存しない＝同値分割）。
- **画面サイズ**は共通関数 `layoutProbe`（画面内・safe-area 内・重なり・44px・横スクロール）を 1 画面 1 回。
- **版数など毎回変わる値は決め打ちしない**：キャッシュ名・件数は sw.js から読む（`swInfo`）。メニューの版表示（common/version.js）は sw.js の CACHE_VERSION と一致することを L10・S8 で確かめる（値そのものは書かない）。旧版の SW はサーバーが配信中の sw.js の `CACHE_VERSION` だけ書き換えて作る（`/__ctl?swver=`）。
- **外部に出ない**：Google Fonts は空の応答で即答（SW の通信も差し替え）。オフラインはサーバーが接続を切って再現（setOffline は SW の fetch に効かないため）。

## 7. 待ち時間の早送り・並列

- **並列**：グループ単位で子プロセスに分け、既定 3 並列（`WORKERS`。v38 で 4→3）。子は自分専用のポート（PORT＋i）でサーバーとブラウザを持つので、オフライン・遅延の再現が他のグループに影響しない。割り振りは重い順（run.mjs の weight）。
- **早送り**：`newPage(..., { clock: true })` のページは Playwright の `page.clock` でタイマーを置き換え、`wait(page, ms)` で一気に進める。素早い連続タップは `frozen()` でページの時刻を止めたまま送る（負荷で CDP が遅れても 350ms を超えない）。
- **実時間のまま**のもの：P2 前半（0.8 秒の境界）、S（Service Worker は page.clock の外）、A2・A5（音の同時発音数は AudioContext の実時間で数えるため）、E5・P7（スクロール・スワイプはブラウザ側の時間）、V6・V7（回転・見た目）。
- **時計の指定**：`newPage` のオプションは opts の1オブジェクトに入れる（`{ initScript, clock: true }`）。第5引数に書くと無視され、実時間で待つことになる（D7・P5・A3 で見つかり、直した。D6 は早送りしても合否が変わらないことを確認して clock を opts に入れた）。日付を使うテストは `clockTime`（時刻を固定）と `timezoneId` を渡し、期待値は固定した時刻から作る。決まりは README「日付・時計」。
- **サーバーとテストは同じ機械で動かす**（S4 の x-served-at をテストの実時計と比べるため。別の機械だと時計のずれで崩れる）。
- `CLOCK=0` で早送りを止められる。早送りあり／なしで合否が同じことを確認済み（README の所要時間の表）。
- **solo の段（T-02・T-09、v35）**：速さを測る項目（A5・WW10・KW10・FW18・HW19）には `solo: true` を付け、run.mjs は WORKERS が 2 以上のとき、ほかのグループが全部終わってから 1 つずつ流す（出力に「（速さ・1 つずつ）」）。並列の負荷で速さの測定が落ちるのを防ぐ。WORKERS=1 は今までどおり。
- **ページ・ブラウザが落ちたときだけ 1 回流し直す（MT-14・T-09、v35。ユーザー「v35 で入れる」）**：項目が `Target crashed`・`Page crashed`・`Browser has been closed`・`browser has disconnected` の例外で止まったときだけ、その項目を 1 回流し直し、2 回目を合否にする（結果に「↻ 流し直し 1 回」、最後にまとめの行）。ふつうの不合格・ほかの例外・時間切れは流し直さない（確かめを弱めない）。コンソールエラー（X1）は 1 回目の分も数える。落ちる原因は WebKit 側でテストの待ち方ではないため、直さず流し直す。
- **時計の巻き戻り（T-25・T-26、v38）**：重いと Playwright の page.clock.runFor(ms) が ms より少なくしか進まないことがある（600 回に 1 回ほど）。押下を受けない時間の直後に押す所は、ページの時刻を読んで確かに過ぎるまで待つ（ハシわたりの passBlock）。描き直し（rAF）で決まる値は、実時間と早送りを交互に、上限つきで待ってから読む。
- **時計の巻き戻りの直し（T-26 ほか、v39）**：Playwright の時計は、実時間に合わせる処理と `runFor` が重なると進んだ時刻が古い値に戻る（直した写しの full 1 回で 95〜110 回、`wait` の分に足りなかった）。`wait` は前後でページの時刻を読み、足りなければ足りない分を進め直す（3 回まで。ページを移ったら何もしない。時間は +約 3%）。FW19（T-24）は長い `until` のあと WebKit で時刻が 5〜9 秒戻るので、回の間を `frozen` で囲み上限 120 秒（`timeout`）。HW14（HS-14）は 2 回のタップの間を `frozen`。WW17（T-27）は時計を止める前にふつうのタップを 1 回して音の準備を済ませる（止めた時計の最初の touchend で AudioContext を作るとページが固まり、CDP のタッチが返らなかった）。CDP のタッチには 10 秒の上限。P9（T-02）はライフが 1 以下になったら開き直して始め直す（後半の条件 `lives >= 2` が満たされず 60 秒回り続けた）。D10（T-07）は `kiriCutOne`（切れたかを cutCount で確かめ、切れなければ別の的で 3 回まで）。確かめの基準は変えていない。
- **止まった項目の流し直し（v39。ユーザー決定「入れる (Recommended)」）**：run.mjs の `STALLED`（1 項目の時間切れ・`locator resolved to` で終わる Timeout で `attempting`/`retrying`/`hidden`/`visible`/`N ×` が無いもの・CDP のタッチの時間切れ）も 1 回だけ流し直す。時間切れの項目は裏で動き続けて次の項目の結果に混ざっていた（P10 の不合格）ので、止まった回の check は記録せず（`live`）、その項目のページを閉じる。ページが落ちたときはブラウザごと起動し直す（MT-14）。項目ごとの上限は `timeout`。

## 8. WebKit

`BROWSER=webkit` で切り替える。CDP（Chromium 専用）で連続タップ・スワイプ・長押しを送る確認（P7, E5, T1〜T4）は WebKit では「対象外」と表示して飛ばす。代わりに T5 は Playwright 共通の `touchscreen.tap` で、ダブルタップ抑止の中心部分（dblclick・gesture・2 回目の touchend）を WebKit でも確かめる。S5 のフォント用キャッシュ（20 件）は、WebKit では Service Worker 自身の通信を差し替えられず外部に出るため Chromium だけ。WebKit での結果と見つかった差（A5 の処理時間）は README。

## 10.75 iPhone の遠隔テストの中継（tests/relay/・common/debug-relay.js、RL）

- **本物の部品をそのまま動かす**：中継（relay.mjs）は子のプロセスとして起動する（`--key 4321` 固定・`--port 0`・`--host 127.0.0.1`。LAN に出さない）。起動の最初の行 `RELAY_READY port=<ポート> key=<合言葉>` から実際のポートを読む。Playwright のページが iPhone の代わり、PC 向けの窓口は fetch、ask.mjs は子のプロセス。どの項目も `withRelays` の finally で中継を止める（失敗・時間切れでも）。念のため worker の終わり（process の exit）でも残りを止める。
- **WebSocket の記録**：ページに initScript で WebSocket を包む小さな仕掛けを入れ、つないだ回数と閉じたときのコード（4001・4002）を `window.__rl` に残す（運び役の動きは変えない）。あわせて Playwright の `websocket` の出来事で回数を数える。「つなぎ直さない」は、つなぎ直しの最初の間隔（1・2 秒）より長い 3.5 秒待って、回数が 1 のままかで確かめる。
- **open・reload のあと**は古い接続が約 100ms 残るので、直前の `/status` の `device.connectedAt` を `/wait?after=` に渡して新しい接続を待つ。
- **ループバック以外 403**（RL7）：この機械に LAN の IPv4 があれば、`--host 0.0.0.0` の中継へそのアドレスからつないで本物の 403 を確かめる。なければその確認は省き、export された判定の関数 `isPcRequest`（接続元・Host・Origin）と `resolveStatic` を直接確かめる（どちらも毎回流す）。
- **open・reload の移る先の URL（RL3・RL11、T-11）**：移る先の URL に `debug=1&relay=1&key=` を付ける（path の `?` と `#` は残す）。sessionStorage の印も残す。RL11 は iPhone で起きたこと（移った先で sessionStorage の印が読めない）のまねとして、印を消してから open・reload し、移った先で 🐞 が出て中継につなぎ直すかを見る。
- **URL の並び（RL12、Node だけ、T-12）**：relay.mjs が export する `orderLanAddresses`・`isVirtualLan`・`lanUrlLines` を直接呼ぶ。ふつうの LAN が先、仮想のネットワーク（アダプタ名・192.168.56.x・172.16〜31.x・169.254.x.x、または MAC の先頭が VirtualBox・VMware・Hyper-V のもの。`isVirtualMac`）は後ろで印つき、先頭に「おすすめ」。名前が「イーサネット 3」で 192.168.57.1・MAC 0a:00:27:… の例は仮想で後ろ、Wi-Fi 192.168.1.13 が先頭の「おすすめ」。
- **X1**：中継を止めている間（RL4）の「WebSocket につながらない」console だけは、RL のページで集計から外す（ほかのエラーは数える）。
- **ask.mjs の引数の読み方**（RL6）は、受け取った args をそのまま返す命令 `rlecho` をテストのページで `YubiDebug.command` に足して確かめる。`--yes` なしの storage は、ページの命令の出来事（subscribe の command）に storage が来ない・localStorage が変わらないことで確かめる。
- **変異テストは作らない**（ゲームの仕組みは変えないため）。効き目は作業用の写しを手で壊して確かめた（2026-10-22）：ask.mjs の `--yes` の確認を外す→RL6、4002 で前の端末を閉じない→RL8、合言葉を確かめない→RL2、「デバッグを終わる」で yubi.relay を消さない→RL5。どれも不合格になった。`..` の確認を 1 つ外しても、`.` で始まる名前の確認と root の中かの確認が残るので RL7 は合格のまま（守りが重なっている）。
- **確かめられないこと**：本物の iPhone の Safari・Wi-Fi・Windows のファイアウォール・自動ロックでの切断は段 4（自宅 PC での接続確認）で人と一緒に確かめる。中継は http なので Service Worker（オフライン・更新）は対象外。

## 11. 減らしたことで見落とす可能性があるもの

1. **実機の iOS Safari ではない**。WebKit（Linux 版）は同じエンジンだが、ダブルタップ拡大・safe-area・ホーム画面起動・音の聞こえ方・消音スイッチは確かめられない（README の実機確認リスト）。
