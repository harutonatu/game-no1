# 統合テストの設計と対応表（ゆびあそび）

使い方は [README.md](README.md)。ここには「何を・なぜ・どこで確かめているか」をまとめる。
（元は一時フォルダの testsuite/design.md・inventory.md。2026-10 に tests/ へ移し、効果音・タッチ操作・スコア欄の桁数の確認を取り込んだ）

## 1. 経緯（棚卸しの要点）

- 以前は修正のたびに一時フォルダへ確認用スクリプトを作っていた。棚卸しの時点で 35 本・判定 563 項目＋観察のみ約 900、全部流すと約 15 分（判定つきの回帰テストだけで 5.5 分）。
- 問題点：画面サイズの総当たりが時間の大半／キャッシュ版数（v4〜v6）の決め打ちで SW を更新するたびに 3〜4 本の期待値を書き換え／環境依存・不安定な判定 2 件／作業ツリーやリポジトリに書き込むスクリプト／観察のみで合否が出ない（十字キー 43px を見ていたのに誰も不合格にしなかった）／Safari の低い横持ち × ブロックを判定つきで見ていなかった（→ K1）。
- これを 1 つのスイートにまとめ、同値分割・境界値・ペアワイズ・リスクで項目を絞った（563 → full 約 200、smoke 約 80）。

## 2. 方針

```
              V  画面サイズ：代表・境界の両側・ペアワイズ 12 行だけ        full（smoke は最も狭い・最も低い画面）
          D/E/S/P/A/T  ブラウザの機能テスト：端末は iPhone 13 の 1 種類    リスクの高いものは smoke
      L/A1  Node：2048 のロジック・sw.js/manifest/HTML の静的検査（0 秒）   すべて smoke
```

- **L（Node）**：`games/2048/index.html` の script を vm で実行し、公開 API `window.Tile2048Logic` を直接呼ぶ。sw.js・manifest・各 HTML は文字列として検査。
- **機能テスト**は端末を iPhone 13 に固定（操作の結果は画面サイズに依存しない＝同値分割）。
- **画面サイズ**は共通関数 `layoutProbe`（画面内・safe-area 内・重なり・44px・横スクロール）を 1 画面 1 回。
- **版数など毎回変わる値は決め打ちしない**：キャッシュ名・件数は sw.js から読む（`swInfo`）。旧版の SW はサーバーが配信中の sw.js の `CACHE_VERSION` だけ書き換えて作る（`/__ctl?swver=`）。
- **外部に出ない**：Google Fonts は空の応答で即答（SW の通信も差し替え）。オフラインはサーバーが接続を切って再現（setOffline は SW の fetch に効かないため）。

## 5. ペアワイズ（V3）

端末 4 × 向き 2 × 起動 2 × 画面 3 ＝ 48 通り → 12 行。どの 2 因子の組（44 組）も 1 回以上出ることを V3 の最初に機械的に確かめる（`pairwiseMissing()`）。1 行目（SE 縦ホーム画面 メニュー）・3 行目（SE 横ホーム画面 2048）は V1・V2 と重ねて流さない。2 行目（SE 横 Safari ブロック）で K1 を発見。

## 7. 待ち時間の早送り・並列

- **並列**：グループ単位で子プロセスに分け、既定 4 並列（`WORKERS`）。子は自分専用のポート（PORT＋i）でサーバーとブラウザを持つので、オフライン・遅延の再現が他のグループに影響しない。割り振りは重い順（run.mjs の weight）。
- **早送り**：`newPage(..., { clock: true })` のページは Playwright の `page.clock` でタイマーを置き換え、`wait(page, ms)` で一気に進める。素早い連続タップは `frozen()` でページの時刻を止めたまま送る（負荷で CDP が遅れても 350ms を超えない）。
- **実時間のまま**のもの：P2 前半（0.8 秒の境界）、S（Service Worker は page.clock の外）、A2・A5（音の同時発音数は AudioContext の実時間で数えるため）、E5・P7（スクロール・スワイプはブラウザ側の時間）、V6・V7（回転・見た目）。
- `CLOCK=0` で早送りを止められる。早送りあり／なしで合否が同じことを確認済み（README の所要時間の表）。

## 8. WebKit

`BROWSER=webkit` で切り替える。CDP（Chromium 専用）で連続タップ・スワイプ・長押しを送る確認（P7, E5, T1〜T4）は WebKit では「対象外」と表示して飛ばす。代わりに T5 は Playwright 共通の `touchscreen.tap` で、ダブルタップ抑止の中心部分（dblclick・gesture・2 回目の touchend）を WebKit でも確かめる。S5 のフォント用キャッシュ（20 件）は、WebKit では Service Worker 自身の通信を差し替えられず外部に出るため Chromium だけ。WebKit での結果と見つかった差（A5 の処理時間）は README。

## 11. 減らしたことで見落とす可能性があるもの

1. **実機の iOS Safari ではない**。WebKit（Linux 版）は同じエンジンだが、ダブルタップ拡大・safe-area・ホーム画面起動・音の聞こえ方・消音スイッチは確かめられない（README の実機確認リスト）。
2. ペアワイズは 2 因子まで。K1 のような「Safari の低い横持ち × ブロック」は SE 以外で見落とす可能性。@media を変えたら V3 の行を増やす。
3. 機能テストは iPhone 13 の 1 画面だけ。
4. 削除した見た目の細部（盤面が最大の正方形、カードの文字が 1 行、色の差、撮影）は自動では気づかない。
5. ブロックパズルのゲームロジック（回転・ライン消去・得点）は直接確かめていない（「得点が増える」「ゲームオーバーになる」だけ）。
6. 早送りしたテストは「タイマーの順序」は本物だが、CSS のアニメーションは実時間のまま。見た目の途中経過は確かめていない。
