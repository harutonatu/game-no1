# 統合テストの設計と対応表（ゆびあそび）

使い方は [README.md](README.md)。ここには「何を・なぜ・どこで確かめているか」をまとめる。
（元は一時フォルダの testsuite/design.md・inventory.md。2026-10 に tests/ へ移し、効果音・タッチ操作・スコア欄の桁数の確認を取り込んだ）

## 1. 経緯（棚卸しの要点）

- 以前は修正のたびに一時フォルダへ確認用スクリプトを作っていた。棚卸しの時点で 35 本・判定 563 項目＋観察のみ約 900、全部流すと約 15 分（判定つきの回帰テストだけで 5.5 分）。
- 問題点：画面サイズの総当たりが時間の大半／キャッシュ版数（v4〜v6）の決め打ちで SW を更新するたびに 3〜4 本の期待値を書き換え／環境依存・不安定な判定 2 件／作業ツリーやリポジトリに書き込むスクリプト／観察のみで合否が出ない（十字キー 43px を見ていたのに誰も不合格にしなかった）／Safari の低い横持ち × ブロックを判定つきで見ていなかった（→ K1）。
- これを 1 つのスイートにまとめ、同値分割・境界値・ペアワイズ・リスクで項目を絞った（563 → full 約 200、smoke 約 80）。

## 2. 方針

```
              V  画面サイズ：代表・境界の両側・ペアワイズ 12 行だけ        full（smoke は最も狭い・最も低い画面）
          D/E/S/P/A/T  ブラウザの機能テスト：端末は iPhone 13 の 1 種類    リスクの高いものは smoke
      L/A1  Node：2048・キリトリのロジック・sw.js/manifest/HTML の静的検査（0 秒）   すべて smoke
```

- **L（Node）**：`games/2048/index.html`・`games/kiritori/index.html` の script を vm で実行し、公開 API `window.Tile2048Logic`・`window.KiritoriLogic` を直接呼ぶ。sw.js・manifest・各 HTML・メニューの GAMES は文字列として検査。
- **機能テスト**は端末を iPhone 13 に固定（操作の結果は画面サイズに依存しない＝同値分割）。
- **画面サイズ**は共通関数 `layoutProbe`（画面内・safe-area 内・重なり・44px・横スクロール）を 1 画面 1 回。
- **版数など毎回変わる値は決め打ちしない**：キャッシュ名・件数は sw.js から読む（`swInfo`）。メニューの版表示（common/version.js）は sw.js の CACHE_VERSION と一致することを L10・S8 で確かめる（値そのものは書かない）。旧版の SW はサーバーが配信中の sw.js の `CACHE_VERSION` だけ書き換えて作る（`/__ctl?swver=`）。
- **外部に出ない**：Google Fonts は空の応答で即答（SW の通信も差し替え）。オフラインはサーバーが接続を切って再現（setOffline は SW の fetch に効かないため）。

## 7. 待ち時間の早送り・並列

- **並列**：グループ単位で子プロセスに分け、既定 4 並列（`WORKERS`）。子は自分専用のポート（PORT＋i）でサーバーとブラウザを持つので、オフライン・遅延の再現が他のグループに影響しない。割り振りは重い順（run.mjs の weight）。
- **早送り**：`newPage(..., { clock: true })` のページは Playwright の `page.clock` でタイマーを置き換え、`wait(page, ms)` で一気に進める。素早い連続タップは `frozen()` でページの時刻を止めたまま送る（負荷で CDP が遅れても 350ms を超えない）。
- **実時間のまま**のもの：P2 前半（0.8 秒の境界）、S（Service Worker は page.clock の外）、A2・A5（音の同時発音数は AudioContext の実時間で数えるため）、E5・P7（スクロール・スワイプはブラウザ側の時間）、V6・V7（回転・見た目）。
- **時計の指定**：`newPage` のオプションは opts の1オブジェクトに入れる（`{ initScript, clock: true }`）。第5引数に書くと無視され、実時間で待つことになる（D7・P5・A3 で見つかり、直した。D6 は早送りしても合否が変わらないことを確認して clock を opts に入れた）。日付を使うテストは `clockTime`（時刻を固定）と `timezoneId` を渡し、期待値は固定した時刻から作る。決まりは README「日付・時計」。
- **サーバーとテストは同じ機械で動かす**（S4 の x-served-at をテストの実時計と比べるため。別の機械だと時計のずれで崩れる）。
- `CLOCK=0` で早送りを止められる。早送りあり／なしで合否が同じことを確認済み（README の所要時間の表）。

## 8. WebKit

`BROWSER=webkit` で切り替える。CDP（Chromium 専用）で連続タップ・スワイプ・長押しを送る確認（P7, E5, T1〜T4）は WebKit では「対象外」と表示して飛ばす。代わりに T5 は Playwright 共通の `touchscreen.tap` で、ダブルタップ抑止の中心部分（dblclick・gesture・2 回目の touchend）を WebKit でも確かめる。S5 のフォント用キャッシュ（20 件）は、WebKit では Service Worker 自身の通信を差し替えられず外部に出るため Chromium だけ。WebKit での結果と見つかった差（A5 の処理時間）は README。

- **期待値の作り方**：半分の速さは決め打ちの値（effective 45・15・3600、seconds 90・7200）と比べる（logic の `AWAY_RATE` を変える変異 MW2 を、logic から作った期待値で見逃さないように）。稼ぎは「同じ保存から Node で `catchUp(st, 90)` した稼ぎ」と同じか（main.js で二重に掛ける MW3 を見つける）。
- **二重に足さない（WW4）**：hidden → 90 秒 → visible のあと、もう一度 visibilitychange・pageshow（persisted）を送り、`lastAway` が同じままか（二重に足すと `lastAway` が 0 秒の報告に置きかわる）。
- **既知の不具合 W-K1（SZ-01）は解消**（2026-10-21、契約 §17.1 A1）：3 時間閉じても `capped` が false だった不具合を直し、WW3 の定数 `KNOWN_CAPPED` を外して合否に含めた（戻りは変異 MW40 で見つける）。
- **レビュー後の直し（WW18、契約 §17.1）**：遊び方の間は `logic().t` もお金も進まず `frames` は増える、おかえりカードの間は進む。rAF だけが止まった間は、`page.clock.pauseAt` → `setSystemTime(+90 秒)` → `resume` で作る（visibilitychange を送らない。effective 45・そのあと二重に足さない）。シートを開いた部署は `#scene` の見える所にあり（シートの上端より上）`aria-expanded="true"` が1つだけ。`#sheetInfo[data-jam]` は、押すと応援でつまりが動くので、応援が切れて使えない間にもう一度押して確かめる。`advance(120)` は Node の `step(0.1)` 1200 回と同じ（ページの中で logic() → advance → logic() を1回の evaluate でする。間に rAF を挟まない）。
- **画面内（WW9）**：横向き（高さ 500 以下）はシートを #goal の上に重ねて出す設計なので、シートを開いた形では #goal の中身との重なりを見ない。シートを閉じた形で、上の帯と #goal のボタン（広げる・注文の札）を別に見る。
- **性能（WW10、CDP）**：ページの時計を早送りしない（実時間）。みなとで全部最大にして CPU 4 倍遅くで 6 秒、`slowFrames`（前のコマから 34ms を超えた数）の増え方が `frames` の増え方の 5% 以下、人 40〜60。1 コマの描画の時間（render の `drawMs`）は `getState` に出ていないので見ていない。
- **効果音（WW14）**：作業音 chop・saw は合わせて 0.4 秒に 1 回まで（間引かれた回は音の部品が動かない）なので、「どの名前も 1 回以上は音の部品が start した」の確認では、作業音はどちらか一方でよい。

## 10.7 デバッグ表示（common/debug.js、DG）

- **無効のときに何もしない**ことが一番大事（全ページで読み込むため）。DG2 は全ページで、オーバーレイの要素・Shadow DOM・`window.YubiDebug` がない、`<html>` の子が HEAD と BODY だけ、console の4つがブラウザの元の関数（`[native code]`）のまま、sessionStorage に書かない、を確かめる。
- **わざと起こすエラー**（DG3）は X1 を不合格にしないよう、そのページだけ console・pageerror の受け取りを「印 DGTEST を含むものは数えない」ものに差し替える（ほかのエラーは今までどおり X1 に入る）。
- **ボタンの置き場所**（DG5）：debug.js は押せる要素（button・a・input・[role=button]・[data-cmd]・[data-action]）を 4px 広げて必ず避け、canvas と文字の行はできるだけ避けて、画面の端に近い空いた所に置く。テストは置いた後のボタンの四角と、見えている押せる要素の四角が1px も交わらないこと（広げない）を、メニューと全ゲームの最初の画面（初回の遊び方を含む）とプレイ中で確かめる。早送り（page.clock）で 1 秒ごとの置き直しも進める。
- **Shadow DOM**：オーバーレイは Shadow DOM の中なので、V11（document.body の文字を数える）には入らない。代わりに DG5 がパネルの中の文字を 12px 以上か調べる。
- **変異テストは作らない**（点数・保存・日付・ルールを変えないため。CLAUDE.md）。効き目は手で8通り壊して確かめた（2026-10-20）：常に有効→DG2・DG3、console.error を数えない→DG3、ボタンを左上に固定→DG5、APP_FILES から外す→DG1・DG6、ない命令で例外→DG4、ログの文字 11px→DG5、sessionStorage に覚えない→DG3、tap で click を送らない→DG4。どれも不合格になった。
- **確かめられないこと**：合成のタップ（`tap` 命令・テスト）は isTrusted が false なので、効果音の開始やダブルタップ拡大の抑止は確かめられない。Safari の「コピー」（クリップボードの許可）も実機で確かめる。

## 11. 減らしたことで見落とす可能性があるもの

1. **実機の iOS Safari ではない**。WebKit（Linux 版）は同じエンジンだが、ダブルタップ拡大・safe-area・ホーム画面起動・音の聞こえ方・消音スイッチは確かめられない（README の実機確認リスト）。
2. ペアワイズは 2 因子まで。K1 のような「Safari の低い横持ち × ブロック」は SE 以外で見落とす可能性。@media を変えたら V3 の行を増やす。
3. 機能テストは iPhone 13 の 1 画面だけ（キリトリの P9 は描く面積の小さい SE 縦）。
4. 削除した見た目の細部（盤面が最大の正方形、カードの文字が 1 行、色の差、撮影）は自動では気づかない。
5. ブロックパズルのゲームロジック（回転・ライン消去・得点）は直接確かめていない（「得点が増える」「ゲームオーバーになる」だけ）。
6. 早送りしたテストは「タイマーの順序」は本物だが、CSS のアニメーションは実時間のまま。見た目の途中経過は確かめていない。
7. キリトリ道場の「手応え」（割れ方・破片・軌跡の光・効果音の聞こえ方）は、数（割れた半分 2 つ・破片あり・軌跡の点が 0.2 秒で消える・音の名前）でしか確かめていない。見た目と、指で隠れずに軌跡が見えるかは実機確認（README のリスト 8）。
8. キリトリ道場のテストは `window.KiritoriGame.snapshot()`（読むだけの確かめ用 API）に頼る。名前や形を変えたら lib.mjs の `kiriSnap` などを合わせる。
