# iPhone の遠隔テスト（中継）の計画

作成日：2026-10-22。ユーザー決定「はい、Aで進めましょう。まずは計画を立案して」（A＝自宅の PC を中継役にして、iPhone の Safari を遠隔で操作する）。課題は [docs/issues.md](issues.md) の T-10。
元の設計メモは [docs/debug.md](debug.md) の 5 章。この文書はそれを「作る順番・分担・合格の基準」にしたものです。

## 1. ねらい

自宅の PC の Claude Code から、**本物の iPhone の Safari** で次のことをする。

| できるようにすること | 例 |
|---|---|
| 読む | 画面の大きさ・safe-area、ボタンの位置と重なり（`layout`）、ゲームの中の数（`state`）、エラー（`logs`） |
| 動かす | デバッグ命令（`win`・`gostar` など）、押す操作のまね（`tap`）、保存データの読み書き（`storage`） |
| まとめて点検する | 12 本のゲームを順に開いて、ボタンの 44px・重なり・画面外を一度に測る（2 段目） |

**できないこと（これまでどおり人の手で確かめる）**：本物の指の感触、効果音の開始、ダブルタップ拡大の抑止、画面の写真（Safari のページからは撮れない）。

## 2. 全体の形

```
 自宅 PC（Windows）                                      iPhone（同じ Wi-Fi）
 ┌──────────────────────────────┐                ┌──────────────────────┐
 │ Claude Code                   │                │ Safari                │
 │   │ node tests/relay/ask.mjs   │                │  http://192.168.x.x:  │
 │   ▼   （HTTP）                 │                │   8790/?debug=1&      │
 │ 中継サーバー tests/relay/relay.mjs│◀─WebSocket──▶│   relay=1&key=合言葉  │
 │   ・ゲームのファイルを配信     │                │  debug.js ＋ 運び役   │
 │   ・iPhone とつなぐ            │                └──────────────────────┘
 └──────────────────────────────┘
```

- **中継サーバー 1 つで、ページの配信と iPhone とのやりとりの両方を行う**。iPhone は PC のアドレス（http）を Safari で開くだけ。
- Claude は `node tests/relay/ask.mjs info` のように命令を送り、結果（JSON）を受け取る。Windows の PowerShell では `curl` が別物（Invoke-WebRequest）なので、curl ではなく Node の小さな道具にする。
- 追加のパッケージは使わない（Node の標準だけ。WebSocket のサーバー側も標準の機能で書く）。リポジトリに `package.json` や `node_modules` を入れない決まりを守るため。

### 決めたこと（理由つき）

| 決めごと | 内容 | 理由 |
|---|---|---|
| 配信の形 | 1 段目は PC から http で配信する | GitHub Pages（https）から暗号化なしの ws:// へはつなげない。https にするには証明書が要り、iPhone への設定が難しい |
| オフライン・更新の確認 | 中継では確かめない。公開版で人が確かめる | http（PC のアドレス）では Service Worker が動かない |
| 運び役の置き場所 | 新しいファイル `common/debug-relay.js`。debug.js は `relay=1` のときだけこれを読み込む | ふだん（`?debug=1` なし）の動きを 1 行も変えない（テスト DG2）。debug.js の中身はほとんど変えない |
| 事前キャッシュ | `debug-relay.js` は `sw.js` の `APP_FILES` に入れない | http でしか使わず、オフラインでは要らない（担当がテスト DG1・L 系と食い違わないか確かめる） |
| 合言葉 | 中継サーバーを起動するたびに短い合言葉（8 文字の英小文字と数字。例：`26g5xuu3`）を作り、画面に出す。iPhone の URL に `key=` で付ける | 同じ Wi-Fi のほかの機械から命令を送れないようにする |
| 書き換える命令 | `storage` の set・remove は、ask.mjs で `--yes` を付けたときだけ送る | 保存データを消さないため |
| ポート | 8790 | 設計メモと同じ |

## 4. やりとりの形（段 0 で詳しく決める案）

| 向き | 形 |
|---|---|
| Claude → 中継 | `POST /run`、本文 `{ "command": "layout", "args": { ... } }`。答えは `YubiDebug.run` の戻り値そのまま（`{ ok, result, command, ms }`）。つながっていなければ `{ ok:false, error:"iPhone が つながっていません" }` |
| Claude → 中継 | `GET /status`：つながっている端末（userAgent・画面の大きさ・開いているページ・最後に話した時刻） |
| Claude → 中継 | `GET /logs?since=id`：iPhone から流れてきたログ |
| 中継 → iPhone | `{ id, command, args }` |
| iPhone → 中継 | `{ id, ...結果 }`、ログは `{ type:"log", entry }`、最初に `{ type:"hello", key, page, info }` |

- 答えを待つのは 10 秒まで。過ぎたら `{ ok:false, error:"時間切れ" }`。
- **つなぎ直し**：画面を消す・別のアプリへ移る・ページを移る（メニュー→ゲーム）と切れる。運び役は 1・2・4・8 秒…（最大 10 秒）の間隔でつなぎ直す。ページを移っても `relay` と `key` は sessionStorage に覚えておく（`?debug=1` と同じ仕組み）。
- 命令を足すときは、今の `YubiDebug.command` に登録する（運び役は命令を知らなくてよい）。
- 1 台だけつなぐ（2 台目がつないだら古いほうを切る）。

## 5. 合格の基準

### クラウド（段 3 の関門）

1. 公開の条件（Chromium の smoke と full、WebKit の smoke）がすべて合格。
2. 新しいテスト（RL 系）が Chromium と WebKit の両方で合格する。少なくとも次を確かめる。
   - 中継を起動 → ページを `?debug=1&relay=1&key=…` で開く → `info`・`layout`・`state`・`logs` が返る
   - 合言葉が違うとつながらない
   - ページを移っても（メニュー→ゲーム）つなぎ直して命令が通る
   - 中継を止めて起動し直すと、自動でつなぎ直す
   - `relay` を付けないときは `debug-relay.js` を読み込まない（DG2 と同じく、ふだんの動きを変えない）
   - `storage` の set は `--yes` が無いと送られない
3. 変異テストは流さない（ゲームの仕組みは変えないため）。

### 自宅 PC（段 4）

1. `node tests/relay/relay.mjs` で起動すると、iPhone で開く URL と合言葉が画面に出る。
2. iPhone の Safari でその URL を開くと、PC 側に「つながりました（iPhone、393×852）」のように出る。
3. Claude が `info`・`layout`・`state` を読める。ほしくだき・もくもくこうばで `state` の数が読める（例：もくもくこうばの置き場の数。SZ-04 の確認に使う）。
4. iPhone の画面を消して点け直すと、10 秒以内につなぎ直す。

## 7. 気をつけること

- **会社 PC では使わない**（監視ソフトがある。CLAUDE.md・handoff.md の決まり）。自宅 PC だけで使う。
- Windows で初めて起動すると、ファイアウォールの確認が出る。「プライベート ネットワーク」だけ許可する（公共の Wi-Fi では使わない）。
- iPhone の自動ロックで画面が消えると切れる。点検の間は自動ロックを長めにする。
- 中継はテストのための道具で、公開版のゲームの動きは変えない。`tests/relay/` は GitHub Pages にも載るが、iPhone からは使わない（PC で動かす道具）。
- 以下は私の推測：iPhone の Safari は、同じ Wi-Fi の PC のアドレス（http）をそのまま開ける。もし開けないときは、PC の IP アドレスとファイアウォールを先に疑う。
