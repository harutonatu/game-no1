# ミチビキ空港 — 部品どうしの約束（契約書）

4人の担当（ロジック・画面・組み込み・テスト）が同じ約束のもとで**並列に**作るための1枚紙です。実装後は tests/design.md に取り込むか削除します。
数値は下書きの値です。ロジック担当が自動プレイ（§4.2 `autoplay`）で測って変えるときは、PM に報告してから §3 を直します。

## 0. ユーザーの決定（2026-10-20、そのまま引用）

ゲームの形：
- 次のゲーム：「ミチビキ空港」
- 得点の形：「色の合う滑走路へ (Recommended)」（選択肢の説明：赤い飛行機は赤い滑走路へ、青は青へ。2〜3色。最初は1色だけで始め、少しずつ色を増やす）
- 終わり方：「3機まで許す」（選択肢の説明：ライフ3つ。長く遊べる代わりに、緊張感は少し下がる）
- 名前：「ミチビキ空港 (Recommended)」

確認事項（§18）への答え。**質問ではなく決定**です：
1. ライフ：「1回で1つ減る (Recommended)」 → ぶつかったら2機でも ♥ は1つ減る（§1.1・`CRASH_LIFE`）
2. 途中保存：「しない (Recommended)」 → アプリを閉じたら次は新しい回（§8.3）
3. 着陸の向き：「向きに沿ったときだけ」 → 入り口の区域に入り、かつ機体の向きが滑走路の向きに沿っているときだけ着陸（§1.1・`LAND_DOT`）。滑走路に矢印を描く（§7.1）
4. おまかせ：「入れる (Recommended)」 → 機体 → 滑走路のタップで、向きに沿って入る道を付ける（§5.3・`suggestPath`）

元になった遊び：フライトコントロール風（docs/game-plan.md 観点3・評価8位）。**遊びの形だけを参考にし、元の作品の名前・絵・音・文言は使わない**。

## 1. ねらいと中身

- 遊びの核は1つ：**飛行機から指でなぞって道を描き、同じ色の滑走路へ、矢印の向きから導く**。ぶつけないように道を引き直す、の繰り返し。回り込む道を描くところに考えどころがある。
- 1回は数分（ライフ3つ）。広告・課金・時間で急かす仕掛けは無し（CLAUDE.md §4 A）。
- 縦画面が基本。横・iPad でも崩さない（§6.2）。

### 1.1 ルール（ロジックの正）

- **場**：決まった大きさの長方形（§3.1 の `LAYOUTS`）。座標の単位は「場の単位」（SE 縦でほぼ 1px）。画面の大きさとは関係なく、描画は拡大・縮小するだけ。
- **出る**：飛行機は場の**端**から現れる。出る `WARN_S`（2.0 秒）前に、その端の位置に**予告の印**（色と形の印つき）を出す。出たら場の中のある点へ向かって**まっすぐ**飛ぶ。
- **道**：飛行機の近く（`PICK_R` 以内）から指でなぞると、その道（点の列）を順にたどる。道を描き直すと前の道は捨てる。**道が終わったら、最後の向きのまま直進**する。
- **端**：場の端に当たると**跳ね返る**（外へ消えない）。道の点は場の内側に収める（§4.2 `setPath`）。
- **着陸**：次の2つを**同じコマで両方**満たしたら着陸（§0 の決定 3）。その瞬間に **+1 点**（`landed` +1）。着陸の動き（滑走路に沿って `LAND_S` 秒、減速して小さくなる）の間は、ほかの機体とぶつからない。終わったら場から消える。
  1. 飛行機の中心が、**同じ色**の開いた滑走路の「入り口の区域」（入り口の点から距離 `ZONE_R` 以下）にある。
  2. 機体の向き `(dx, dy)` と滑走路の向き `(rdx, rdy)`（入り口 → 奥）の内積 `dx*rdx + dy*rdy` が **`LAND_DOT`（0.7、約45度以内）以上**。角度の関数は使わない（§1.2）。
  - 区域の中にいる間は毎コマ判定する（道をたどって区域の中で向きが直れば、そのコマで着陸する）。
  - **色が合っていても向きが違う**ときは、着陸せずにそのまま通り過ぎる（罰なし）。区域に入って最初に向きが違ったコマで、出来事 `wrongway` を1回だけ出す（区域を出るまで、もう出さない。出てまた入れば、また出す）。画面はその滑走路の矢印を一瞬光らせる（§7.3）。
  - **色が違う**滑走路の区域・まだ開いていない滑走路は、通り過ぎるだけ（罰なし・出来事なし）。
- **ぶつかる**：飛んでいる2機の中心の距離が `CRASH_D` 未満になると、**その2機は消え、ライフが `CRASH_LIFE`（1）減る**（§0 の決定 1）。同じコマで別の組もぶつかれば、組ごとに減る。1機が同時に2機とぶつかる場合は、番号（id）の小さい組から順に数え、消えた機体は次の組に入れない。
- **近すぎる**：2機の距離が `NEAR_D` 未満なら、2機とも `near: true`（画面では赤く光る）。
- **終わり**：ライフが 0 になったら終わり（`over: true`）。それ以後の `update` は何も変えない。
- **ひと息**：ぶつかったら、次に出るまでの時間を `CRASH_BREATH`（2.0 秒）のばす（惜しい負けから立て直せるように）。
- **色が増える**：最初は1色（あか）だけ。着陸数が `COLOR_STEPS` に達すると、次の色の滑走路が開く（2色 → 3色）。開いた直後に出る1機目は、必ずその新しい色。
- **点数**：着陸した機数（`landed`）だけ。ベストは「いちばん多い着陸数」。

### 1.2 時間の進め方（固定ステップ）

- ロジックは**1コマ＝`STEP`（1/60 秒）**ずつ進む。画面の速さ（60Hz・120Hz）や重さに関係なく、同じ入力なら同じ結果。
- 時間は「コマ数 `tick`」で数える（秒は `tick * STEP`）。予告・出る時刻・着陸の動きもコマ数で持つ。
- 乱数は種つき（mulberry32）。乱数の状態は state の中の整数（`rng`）として持ち、`update` が新しい値を返す（`Math.random` は使わない）。
- 角度（`Math.sin`・`Math.cos`・`Math.atan2`）はロジックでは使わない。向きは単位ベクトル（`dx`・`dy`）で持ち、正規化は `Math.sqrt` だけ（ブラウザと Node で同じ値になるように）。

### 3.2 色（`COLORS`、id は配列の番号 0〜2）

色だけに頼らない：飛行機の胴・滑走路・予告の印・遊び方に、**同じ形の印**を必ず付ける。色はいろびん・まとめてポンの Okabe-Ito 系に合わせる（実際の hex はいろびんの `COLORS` から写してよい）。

| id | key | name | hex（目安） | mark | 開く着陸数 |
|---|---|---|---|---|---|
| 0 | `red` | あか | `#D55E00` | ○ | 0（最初から） |
| 1 | `blue` | あお | `#0072B2` | △ | 4 |
| 2 | `yellow` | きいろ | `#F0E442`（白い背景では濃いふちを付ける） | □ | 12 |

### 3.3 滑走路（`RUNWAYS[layout]`、色 id の順）

入り口の点 `(ex, ey)` と、滑走路の向き `(dx, dy)`（入り口から奥へ。単位ベクトルで、上下左右のどれか）。区域は入り口の点から半径 `ZONE_R`。着陸できるのは、この向きに沿って入ったときだけ（§1.1）。

| layout | 0 あか | 1 あお | 2 きいろ |
|---|---|---|---|
| `tall`（320×520） | (100, 170)・(1, 0) | (220, 330)・(−1, 0) | (70, 300)・(0, 1) |
| `wide`（520×320） | (130, 100)・(1, 0) | (410, 220)・(−1, 0) | (260, 210)・(0, −1) |

（下書きからの変更：向きのルールで入り口の手前に余地が要るため、tall のあかを x 90 → 100、tall のあおを x 230 → 220、wide のあおを x 390 → 410、wide のきいろを「(420, 60)・下向き」（入り口が上の端に近すぎて回り込めない）から「(260, 210)・上向き」（下から入る）に変えた。PM が下の決まり 1〜4 を計算で確かめ済み。）

- まだ開いていない滑走路も場に描く（灰色・「×」の札・矢印も灰色で）。開くときに色が付く（§7.3）。場所が途中で変わらないので、覚えて遊べる。
- **置き方の決まり**（A は FL1 で確かめられる形にする）：
  1. 滑走路どうし・場の端と近すぎない（区域の外側どうしで 60 以上、区域の外側が端から 40 以上）。
  2. **入り口の手前に回り込む余地がある**：入り口から向きの逆へ `APPROACH_ROOM`（80）の線分（「手前の通り道」）が、場の内側（端から `PLANE_R` 以上）に収まる。入り口が近くの場の端を向かない（入り口の向きの逆側にある端まで 80 以上）。
  3. 手前の通り道が、ほかの滑走路の帯（幅の外側）と区域の中心から `ZONE_R + PLANE_R`（34）以上離れている（回り込む道がほかの滑走路をかすめない）。
  4. 奥（入り口から向きへ `RUNWAY_LEN`）も場の内側に収まる。
- 位置を変えたら表を直して PM へ報告する。

### 3.4 難しさ（`landed`＝着陸数で決まる。時間では決めない）

| 関数 | 式（下書き） | 例 |
|---|---|---|
| `colorsFor(landed)` | `COLOR_STEPS` で 1・2・3 | 0〜3 → 1、4〜11 → 2、12〜 → 3 |
| `spawnInterval(landed)` | `max(2.0, 6.5 − 0.14 × min(n, 10) − 0.22 × max(0, n − 10))` 秒（n＝着陸数。§19 C1）。実際の間隔は乱数で ×0.85〜1.15 | 0 → 6.5、10 → 5.1、15 → 4.0、20 → 2.9、24 → 2.02、25〜 → 2.0 |
| `maxAlive(landed)` | `min(MAX_PLANES, 3 + floor(landed / 4))`。場にいる機体（着陸の動き中を除く）＋予告がこの数に達したら、次の予告を出さずに待つ | 0 → 3、8 → 5、20 → 8、28〜 → 10 |
| `kindFor(landed, r)` | `landed >= 10` で 20% が slow、`landed >= 24` で 15% が fast、残りは normal（控えめに混ぜる） | — |

- 色は、開いている色から等しい確率。開いた直後の1機目だけは新しい色（§1.1）。
- 出る位置：4つの辺から、辺の長さに比例した確率で1つ選び、辺の 15〜85% の位置。場の内側 `PLANE_R` の所に出す。向きは、場の中央の箱（各軸 25〜75%）の乱数の点へ向かう単位ベクトル。
- **回の1機目だけ**は、あかの滑走路の手前側の辺（入り口の向きの逆の辺。tall・wide とも左の辺）の、入り口の線から場の中央の側へ 100〜140 ずらした所（tall は y 270〜310、wide は y 200〜240）から出し、**手前の点**（入り口から向きの逆へ `APPROACH_D`。tall (52, 170)・wide (82, 100)）へ向かってまっすぐ飛ばす（§19 B4）。手前の点まで約 4 秒あるので、そこから矢印の向きへ短くなぞるだけで入れる。何もしなければ手前の点を通って入り口の横を抜ける（区域に入らないので、ひとりでには着陸しない）。この1機目だけは、向きが §3.4 の「場の中央の箱へ向かう」に当てはまらない。
- **調整の目安**（A が §4.2 `autoplay` で各 200 回測り、§3.5 に書く。向きのルールで下書きより難しくなるので見直した）：
  - `none`（何もしない）：着陸の中央が **3 以下**（偶然に向きまで合うことは少ない。何もしないと勝てない）。
  - `naive`（出たらすぐ、向きを見ずに入り口へ一直線）：着陸の中央が `straight` の **半分以下**（向きのルールが効いている＝回り込む道を描く意味がある）。
  - `straight`（出たらすぐ、おまかせの道 `suggestPath`＝手前から向きに沿って入る道）：着陸の中央が **12〜50**。これより多ければ、おまかせだけで済んでいる（考えどころが無い）ので `spawnInterval` の下限を下げるか `maxAlive` を上げる。少なければ、回り込む道どうしがぶつかりすぎているので、`spawnInterval` の始まり（6.5）を上げるか、`maxAlive` の増え方をゆるめる。
  - `lazy`（出てから 1.5 秒たってから、おまかせの道）：`straight` より少ない。
  - 1回の長さ（`straight`）の中央が **2〜5 分**（回り込む分、1機にかかる時間が長いので、上限を下書きの 6 分から下げた）。
  - 回の最初の5機（`straight`）のうち、ぶつからずに着陸する割合が 80% 以上（はじめの1分で嫌にならない）。
  - 1機目が着陸するまでの秒（人間らしい打ち手 `avg`：出てから 1〜4 秒後に道を付ける）の中央が **8 秒以下**（はじめの1機でじれない。§19 B4）。
  - 慣れた人（`bot`）ほど早く終わり、ゆっくりの人（`slow`）の着陸数はほぼ変わらない（後半の詰まり方だけを速める。§19 C1）。
- 数値（§3.1・§3.4）は、ロジック担当が測って調整してよい。変えたら PM に報告して §3 を直す。

## 4. ロジックの API（`games/michibiki/logic.js`、担当A）

UMD で `window.MichibikiLogic` と Node の `module.exports`。DOM・時計・`Math.random`・localStorage にはさわらない。例外を外へ出さない（おかしな引数は `null`・`{ ok: false }`・元の state のまま）。

### 4.1 状態の形（イミュータブル）

毎回新しい state を返し、元を変えない。ただし性能のため、**変わらない配列（道の点の列など）は前の state と共有してよい**（共有する配列は凍結する）。道は点の列を切り詰めず、たどった位置を `pathI` で持つ。

```js
state = {
  seed, rng,                 // 種と、乱数の今の状態（32bit 整数）
  layout, w, h,              // 'tall' | 'wide' と場の大きさ
  tick,                      // 始めてからのコマ数
  landed, lives, over,       // 着陸数・ライフ・終わったか
  colors,                    // 開いている色の数（1〜3）
  nextId,                    // 次の機体の id（0 から増える。使い回さない）
  nextSpawnTick,             // 次に予告を出すコマ
  planes: [{
    id, color, kind,         // 色 id・'slow'|'normal'|'fast'
    x, y, dx, dy, speed,     // 位置・向き（単位ベクトル）・速さ（単位/秒）
    path, pathI,             // 道（[[x,y], ...]、凍結）と、次に向かう点の番号。道が無ければ path: null
    guided,                  // 道が同じ色の区域に向きに沿って入るなら true（§4.2 setPath。画面で道を太く・✓）
    near,                    // 近すぎるか
    wrongIn,                 // 向きが違って wrongway を出した区域の色 id。区域の外なら null（出来事を1回にするため）
    phase,                   // 'fly' | 'land'
    landTick                 // 着陸を始めたコマ（phase 'land' のとき）
  }],
  warns: [{ id, color, kind, x, y, dx, dy, spawnTick }],  // 予告（まだ出ていない機体）
  stats: { crashes, guidedLandings, freeLandings, bounces, wrongWays }  // 道で導いた着陸と、道なしで着いた着陸、逆向きの通過
}
```

### 4.2 関数

```js
MichibikiLogic = {
  // §3 の定数・COLORS・RUNWAYS をすべて公開（凍結）

  makeRng(seed) → () => number                     // テストと autoplay 用（state の中では rng を整数で持つ）
  newGame(seed, layout = 'tall') → state            // 予告1つ（spawnTick = FIRST_SPAWN_S）を持った始まりの state。layout が変なら 'tall'
  update(state) → { state, events }                 // 1コマ進める。over なら { state（同じもの）, events: [] }
  advance(state, n) → { state, events }             // n コマ進める（events はつなげる）。n は 0〜36000 の整数、それ以外は 0
  //  1コマの順番：①予告の時刻が来たら出す（安全距離を見て、だめなら 0.5 秒待つ）→ ②動かす（道をたどる・直進・端で跳ね返る）
  //            → ③着陸の判定（同じ色の開いた区域の中で、向きの内積が LAND_DOT 以上の fly の機体。
  //               区域の中で内積が足りなければ wrongway（wrongIn で1回だけ）。区域を出たら wrongIn = null）
  //            → ④着陸の動きが終わった機体を消す
  //            → ⑤ぶつかる判定（fly どうし）→ ⑥近すぎる判定 → ⑦ライフ 0 なら over → ⑧次の予告を決める（色の解放・間隔・maxAlive）

  setPath(state, id, points) → { state, ok, guided, wrongWay, reason }
  //  points = [[x,y], ...]（場の単位）。指の点の列をそのまま渡してよい。中で次をする：
  //   ・場の内側（PLANE_R〜w−PLANE_R、PLANE_R〜h−PLANE_R）に収める
  //   ・PATH_STEP 未満の点を間引く・MAX_PATH を超えた分を捨てる
  //   ・機体の今の位置から PATH_STEP 未満の先頭の点を捨てる
  //   ・guided: true … 道の点のうち、同じ色の開いた区域の中にある点で、1つ前の点（先頭なら機体の位置）からの
  //     向きと滑走路の向きの内積が LAND_DOT 以上のものがある（＝この道をたどれば着陸する）
  //   ・wrongWay: true … 道が同じ色の開いた区域に入るが、どの点でも向きが足りない（画面のヒントに使ってよい）
  //  だめなとき（state はそのまま）：reason 'over'|'noplane'|'landing'|'empty'（id が無い・着陸中・点が無い・形が変）
  clearPath(state, id) → state                      // 道を捨てる（そのまま直進）
  pickPlane(state, x, y) → id | null                // (x,y) から PICK_R 以内の fly の機体で一番近いもの。同じ距離なら id の小さい方
  suggestPath(state, id, color = 機体の色) → [[x,y], ...] | null
  //  おまかせの道（向きに沿って入る道）。PATH_STEP 間隔の点で、次の順に通る：
  //   機体の位置 →（必要なら回り込む点）→ 手前の点（入り口から向きの逆へ APPROACH_D）→ 入り口 → 奥へ 10
  //  ・手前の点 → 入り口 → 奥 はまっすぐ（滑走路の向きそのもの。区域に入るときの内積は 1）。
  //  ・機体から手前の点へ向かう向きと滑走路の向きの内積が 0 未満（横や奥の側から来る）なら、手前の通り道の横へ
  //    回り込む点を 1〜2 つ足す（機体のいる側。真後ろなら場の中央に近い側）。回り込む点も場の内側に収める。
  //  ・曲がりが急すぎない：道の途中の曲がり（となりの区間の向きの内積）は 0 以上（90度以内）。機体の今の向きと
  //    最初の区間の間は数えない。場の端で回り込めないときだけ 90度を超えてよい（最後の区間は必ず滑走路の向き）。
  //  ・途中でほかの滑走路の区域を通っても、色が違えば素通り（§1.1）。
  //  「タップでおまかせ」（§5.3）・キーボード・autoplay・テストで使う。閉じた色・無い id は null
  forceSpawn(state, { color?, kind?, edge?, at? }) → state   // テストとデバッグ用：すぐに予告を足す（at は 0〜1 の辺の位置）
  colorsFor(landed), spawnInterval(landed), maxAlive(landed), kindFor(landed, r)   // §3.4
  runwaysFor(state) → [{ color, ex, ey, dx, dy, open }]       // 今の layout の滑走路と開いているか
  validateBest(raw) → number                        // 安全な整数で 0 以上ならその値、それ以外 0
  recordBest(prev, landed) → { best, improved }     // 同じ値は improved: false
  validateFlag(raw) → boolean                       // '1' のときだけ true
  colorName(id) → string                            // 'あか' など。範囲外は ''
  autoplay(seed, { policy = 'straight', layout = 'tall', maxSeconds = 900 } = {}) → { landed, crashes, seconds, maxAliveSeen, guidedLandings, freeLandings, wrongWays }
  //  policy：'none'（何もしない）・'naive'（出た瞬間に、向きを見ず入り口へ一直線の道）
  //         ・'straight'（出た瞬間に suggestPath＝向きに沿って入る道）・'lazy'（出て 1.5 秒後に suggestPath）。
  //  画面なしで Node で回す。中毒性・品質の担当が数字を出すのに使う
}
```

## 5. 入力の API（`games/michibiki/input.js`、担当B）

```js
MichibikiInput.attach(canvas, {
  toField(clientX, clientY) → [x, y],     // render が渡す（画面の座標 → 場の単位）
  onStart(pointerId, [x, y]) → boolean,   // main：pickPlane で機体があれば true（なぞり開始）
  onMove(pointerId, [x, y]),              // main：点を足す（1コマに1回 setPath にまとめる）
  onEnd(pointerId, [x, y], { tap }),      // tap：動いた距離が 10px 未満で 300ms 以内
  onCancel(pointerId),
  onCommand(name)                         // キーボード（§5.4）
}) → detach()
```

### 5.1 なぞる
- `pointerdown` の点から `PICK_R` 以内に機体があれば、その機体の道を描き始める。無ければ何もしない（場のスクロール・拡大もしない）。その機体をほかの指がなぞっていれば、新しい指は無視する（§19 A7）。
- 最初の `setPath` では、機体から `PICK_R` 以内にある先頭の点を捨てる（うしろをつかんで前へなぞっても Uターンしない。§19 A1）。指を離したとき、まだなぞり始めていなければ（場の単位 8 未満しか動いていない）タップとして扱う（§19 A4）。
- `pointermove` で点を足す。指の点はコマより細かく来るので、点は貯めて、**1コマに1回だけ** `setPath(state, id, 今までの点)` を呼ぶ（main が行う）。描いている間も機体は動き、描いた道をたどり始める。
- `pointerup` で最後の `setPath`。描いている途中で機体が着陸・衝突で消えたら、その指の線は捨てる。
- **同時に3本の指まで**（3機を同時に導ける）。4本目以降は無視（iPad の4〜5本指ジェスチャーと干渉しないため。ピカッと早押し PK-27 の教訓）。`pointerId` ごとに分ける。`pointercancel` はその指の線を捨てる（道はそこまでで確定）。
- canvas は `touch-action: none`。ページ全体はダブルタップ拡大の抑止（既存のゲームと同じ方法）。

### 5.2 道の見た目（render が描く）
- 描いている道：機体の色の点線。道が同じ色の区域に向きに沿って入る（`guided`）と、**実線に変わり、終わりに ✓**、音 `lock`（描いている間に初めて guided になった瞬間だけ）。区域に入っても向きが違う（`wrongWay`）ときは点線のまま（✓ を出さない）。
- たどった所から消えていく（機体の後ろの道は描かない）。

### 5.3 タップでおまかせ（片手・高齢者向けの助け）
- §0 の決定 4 で入れる。機体を**タップ**（なぞらずに離す）すると、その機体を選ぶ（輪で囲む・音 `pick`）。続けて**滑走路をタップ**すると、`suggestPath(state, id, その滑走路の色)` の道（手前を回って、矢印の向きから入る道）を付ける。滑走路のタップは、帯・区域・案内の帯のどこでもよい。場の空いた所をタップすると選びをやめる。
- おまかせの道は、ほかの機体を避けないので、ぶつかることもある（考えどころは残る）。遊び方には書かず、ヒントで1回だけ教える（§8.5）。

### 5.4 キーボード
- `←` `→`：機体を id の順に選ぶ（選んだ機体に輪）。`Tab` は横取りせず、ふつうにボタンへ移る（§19 A8）。
- `1` `2` `3`：選んだ機体に、その色の滑走路へのおまかせの道（§5.3 と同じ）。`Enter`：自分の色の滑走路へ。
- `P`・`Esc`：一時停止／つづける。`M`：音。`?`：遊び方。カードが開いているときは場の操作をしない。

### 6.2 配置
- **縦向き**：上から ヘッダー（← メニュー・名前・？・Ⅱ・♪、44px）→ 点数の帯（ちゃくりく・ベスト・♥）→ 場（残りの高さいっぱい）→ `#hint`。
- 場は `LAYOUTS` の比を保って、使える所に収まる最大の大きさ（余りは場の外の色）。縦向きの画面では `tall`、横向き（幅 > 高さ）では `wide` で**回を始める**。
- **横向き（高さ 500px 以下）**：ヘッダーと点数の帯を1行（44px）にまとめ、場をその下に。SE 横（568×270）でも場の倍率が 0.7 以上になること。倍率が 0.75 未満なら、ヒントに「たてむきの ほうが あそびやすいよ」を1回だけ出す。
- **回の途中で向き・大きさが変わったら**、layout は変えず（場の形はそのまま）倍率だけ直し、遊んでいる途中（その回で機体が1機でも出た後。§19 A6）なら**一時停止にする**（急に小さくなって不公平にならないように）。次の回から新しい向きの layout。
- iPad：倍率の上限は 2.0（大きくなりすぎない）。safe-area の内側に収める。

```js
  play(events),                 // 出来事の演出を始める（時間は rAF の実時間。ロジックは待たない）
  setCalm(bool), pause(), resume(), finishAll(),
  scale, frames, lastDrawMs,     // テスト用
  drawLog                        // テスト用：最後に描いた1コマの記録
  //  { marks: [{ kind: 'plane'|'runway'|'warn', color, x, y }],          // 印（○△□）を描いた所（場の単位）
  //    arrows: [{ color, x, y, dx, dy, open, lit }] }                    // 滑走路の矢印（向き・開いているか・光っているか）

```

### 7.1 機体と滑走路
- 機体：上から見た小さな飛行機（胴・主翼・尾翼）を向きに合わせて回す。胴に**色の印（○△□）**を白抜きで。slow はプロペラ機（少し丸い）、fast はジェット（細い）。大きさは同じ（当たりの大きさが種類で変わらない）。
- `near` の機体：赤い輪が点滅（動きを減らす設定では点滅せず、太い赤い輪）。
- 滑走路：色の帯に白い中心線、入り口の区域は同じ色のうすい円、帯の横に大きく印（○△□）。開いていない滑走路は灰色と「×」（矢印も灰色で描く。覚えて遊べるように）。
- **向きの矢印**（§0 の決定 3。色覚に頼らない）：入り口の側に、滑走路の向き（入り口 → 奥）を指す**太い矢印（»の形、白抜き＋濃いふち）**を描く。形だけで向きが分かること（色を消しても読める）。大きさは `ZONE_R` 程度で、機体より目立つ。
- **案内の帯**：入り口から向きの逆へ `APPROACH_D` の長さ、幅 `RUNWAY_W` の、うすい帯（入り口から遠いほど薄くなる）を描く。「ここから入る」が分かるように。帯は当たり判定を持たない（見た目だけ）。

### 7.2 予告の印
- 出る端に、色と印つきの半円と「！」。`WARN_S` の間、少しずつ濃くなる（動きを減らす設定では濃さだけ変える）。

### 7.3 演出（気持ちいい所を作り込む）
- **着陸**：機体が滑走路に沿って減速しながら小さくなり、滑走路が一瞬光る。`+1` が浮かぶ。着陸数が 5 の倍数のときは少し大きく光る。
- **新しい滑走路が開く**：灰色から色が広がり、印が弾む。ヒント「あおい ひこうきが くるよ！ △の かっそうろへ」。
- **ぶつかる**：2機が光ってはじけ、場が少し揺れる。**ロジックを 0.4 秒止める**（main が `update` を呼ばない。何が起きたか分かるように）。♥ が1つ割れる。
- **跳ね返る**：端に小さな波紋。
- **逆向きで入った**（`wrongway`）：その滑走路の矢印を 0.6 秒、明るく光らせて少し大きくする（`drawLog.arrows[].lit` が true）。機体には何もしない（責めない）。
- 動きを減らす設定：揺れ・粒・点滅なし（矢印は光らせるが大きさは変えない）。止める 0.4 秒はそのまま。
- 性能：機体 10・道 400 点 × 3 本で、SE 相当（CPU 4倍遅く）で1コマの描画 8ms 以内（FW18）。何も動いていないとき（一時停止・カード）は rAF を止める。

## 8. 進行（`games/michibiki/main.js`、担当B）

### 8.1 状態の流れ
- 起動：`document.title` と `#gameTitle` を `NAME` に。ベストを `validateBest` で読む。初回（`michibiki.help` が無い）は遊び方カード（`help`）、閉じたら回を始める。2回目からは**すぐ始める**（`playing`）。
- 回を始める：種は `Date.now() >>> 0`、layout は §6.2。`newGame` → `playing`。音 `start`。
- `playing`：rAF ごとに、経過時間（上限 0.1 秒）を貯め、`STEP` ごとに `update`（1回の rAF で最大 6 コマ）。出来事は `render.play` と効果音に渡す。
- `over`：ベストを `recordBest` → 保存（「ベスト こうしん！」は回を始めたときのベストと比べる。§19 A2）。0.6 秒後に終わりのカード（§8.4）。
- 一時停止（`#pauseBtn`・`P`・hidden・向きの変化）：`paused`。カードは「ひとやすみ」、`#resumeBtn`・`#restartBtn`・`#back`。場はうすく見えたまま（次の手を考えられる）。描いている途中の指の線は、そこまでで確定。

### 8.2 中断・タイマー（ハシわたり・いろびんの教訓）
- タイマーは `later(fn, ms)` だけで作り、`clearLater()` は回を始めるとき・メニューへ・`pagehide` で呼ぶ。回を始めるたびに `runId` +1、古い続きは動かない。
- `pageshow` で、`pagehide` に消された続きを戻す：`over` なのにカードが無ければ終わりのカードを出す、消えなくなったヒントを消す、カードの「押せない」を外し直す（§19 A3）。
- `visibilitychange` で hidden：`playing` なら `paused`（ロジックを進めない。戻ったときに貯めた時間を捨てる）。visible でも自動では再開しない（「つづける」で再開）。
- 遊び方カードを開いている間も止まる。閉じたら、遊んでいた途中なら一時停止カードに戻る。

### 8.3 保存
- `michibiki.best`：着陸のたびに、ベストを超えていたらすぐ更新し、回が終わったときにも `recordBest` で更新（文字列の整数。回の途中でやめても消えない。§19 A2）。
- `michibiki.help`：遊び方を閉じたら `'1'`。
- 効果音の設定は共通の `blockpuzzle.sound`（sfx.js が扱う）。
- **途中保存はしない**（リアルタイムなので。§0 の決定 2）。アプリを閉じたら次は新しい回。
- 読み書きは `try/catch`（保存できなくても遊べる）。壊れた値は 0・false として扱い、落ちない。ほかのゲームのキーに触らない。

### 8.4 終わりのカード
- 見出し「おしまい！」、本文「N き ちゃくりく」。ベスト更新なら「ベスト こうしん！」（音 `best`）。更新でなければ、ベストとの差が 3 以内なら「あと N きで ベスト！」（惜しい負け方）。
- 小さく「みちびいた N き・ぶつかった 3かい」（`stats`）。
- `#againBtn`・`#menuBtn`。カードが出た直後 0.6 秒はどのボタンも押せない（連打の誤タップ防止。見た目は同じ）。

### 8.5 遊び方とヒント
- 遊び方（3項目以内、SE 縦横でスクロールなしで「わかった」が押せる）：
  1. 「ひこうきから ゆびで なぞると、その みちを とぶよ」
  2. 「おなじ いろ・おなじ しるしの かっそうろへ、やじるしの むきから はいると 1てん」（横に、矢印の向きから入る道と、逆から入って ✕ の小さな絵）
  3. 「ぶつかると ♥が へるよ。♥が なくなったら おしまい」
- はじめの1機が出て 3 秒たっても道が無ければ、機体から案内の帯を通って矢印の向きから入口へ指が動く絵と「ひこうきから なぞってね」（1回の回で1度だけ）。
- `wrongway` が出たとき「やじるしの むきから はいろう」。**最初の数回だけ**：1回の回で 3 回まで、かつ その回の着陸が 5 機になるまで（慣れた人には出さない）。
- はじめて `near` が出たとき「あかく ひかったら ぶつかりそう！」。
- はじめて機体をタップしたとき「かっそうろを タップしても いいよ」（§5.3）。
- ヒントは出しっぱなしにせず 3 秒で消す。

## 14. これまでの教訓（最初から入れておく約束）

1. **表示の1ずれ**：`#score`・`#lives` は `getState()` の値をそのまま出す（FW1・FW2）。
2. **横向きでの重なり**：高さ 500px 以下の配置を契約に書いた（§6.2）。矩形で検査（FW6）。
3. **裏に回す・遊び方を開く**：ロジックを止める（§8.2、FW5、MF15）。リアルタイムなので特に大事。
4. **キーボード**：機体を選んで滑走路へ（§5.4、FW8）。
5. **色覚**：Okabe-Ito 系＋印（§3.2、FW11）。
6. **タイマーの片付け**：`later`・`clearLater`・`runId`（§8.2）。
7. **結果カード直後の誤タップ**：0.6 秒押せない（§8.4、MF17）。
8. **空振りのテスト**：無いときに合格にしない（§13.3）。
9. **決定的**：固定ステップ・種つきの乱数・角度の関数を使わない（§1.2、FL7）。
10. **iPad の多本指**：同時に3本まで（§5.1、FW15）。
11. **早送りと canvas**：テストは `manual(true)` と `tick(n)` で進め、ページの時計の早送りに頼らない（キリトリの P9 のように描画で遅くならない）。
12. **向きは形で伝える**：着陸の向きは色ではなく矢印の形と案内の帯で示し、逆向きは責めずに矢印を光らせる（§7.1・§7.3、FW19、MF18〜24）。
