# あまいものあつめ：ありんこが角砂糖の上を歩く・どこから取るか（道のりで近い所から）

- 作成：2026-11-06（PM・Opus）。状態：**直した（§3。版は上げていない・公開前）**。
- ユーザーの言葉（そのまま）：「角砂糖の上を歩いてる？　あと、どこの角砂糖から取るか、という判断だけど、直線距離が近いところから取ってない？経路の1番近いところから、に変更できますか？」（v67・84 面の画面の録画。1 コマ：`amai-route/video-84.png`）

## 1. PM が調べたこと（事実）
- **取る角砂糖の選び方**（`logic.js` の `orderFor`・`findTarget`）：巣（絵の下のまん中）からの「距離のようなもの」`|2x−(W−1)| + 2(H−y)` で全マスの順番を**最初に 1 回だけ**決め、その順で「ふち」（絵のはしの行・列、または外につながった空きのとなり）の角砂糖を取る。**途中の角砂糖や道のりは見ていない**（ユーザーの見立てのとおり、まっすぐの近さで選んでいる）。
- **歩く道**（`render.js` の `findRoute`）：空いているマスと外の枠だけを幅優先でたどる。ただし ①「logic ではもう運ばれたが、前のありんこがまだ持ち上げていないマス」も歩けるとしている（v55 の直し）②道が見つからないときは絵の外の左右から手を伸ばす予備の道。録画では、パンダの体のまん中を縦に並んで歩く列と、絵の上の外枠を回って上の行へ行く列が見える。v67 で背景をうめて**絵の中の空きがほぼ無くなった**ので、①で「まだ角砂糖が見えているマス」の上を通る道が増えた見込み（推測。担当が確かめる）。

## 2. 決めたこと（PM 案）
- **A. 角砂糖の上を歩かない**：見えている角砂糖の上は通らない。①の「まだ持ち上げていないマス」を通るときは、そのマスの角砂糖を先に消す（持ち上げる）か、そのマスを通らない道にする。予備の道（②）に落ちる割合を測り、ほぼ 0 にする。
- **B. 道のりでいちばん近い角砂糖から取る**：巣から、空いたマスと外の枠を通って**歩く道のりがいちばん短い**ふちの角砂糖を取る（同じ道のりなら今の順番で決める）。
  - これは**遊びの決まり**が変わる（どの角砂糖が先に無くなるか・押した手の結果）。面の作り（解けるかの確かめ）・難しさ・保存の再生に関わる。
  - 保存：決まりが変わるので、前の版の途中の保存は**同じ面の最初から**（`picSig` に決まりの版を混ぜる・または保存の版を上げる）。ベスト・ずかん・花輪は変えない。
  - 性能：面を作るときは何千回も運ぶのをまねるので、道のりの計算は速く（外が広がるたびに増やす形の距離の表など）。AL11（ふつう 50ms）・ちょうせん 150ms は下げない。入らなければ止まって報告。
  - 難しさを測り直し、目安（amai-more.md §4.1・amai-bg.md §7）から大きく外れたら止まって報告。

## 3. 直した結果（2026-11-06。担当 Opus。事実。推測は「推測」と書く）

### 3.1 A：角砂糖の上を歩いて見えた原因
- **録画で起きていたこと（事実）**：録画（84 面）では、ありんこと道の線が**わくから出る所も含めて全部、左へ約 108pt（録画の画素で約 325px）ずれて**描かれていた（わく 2 の真上でなく、その左を縦に歩く）。道そのものは空いたマスを通っていたが、描く位置がずれたので、パンダの体の上を縦に歩いて見えた。
- **直接の原因**：`render.js` は、描く板 `#fx`（`position: fixed`）の位置を `layout()` のときだけ測って使い続けていた（毎コマ測らない）。ありんこの位置は運ぶたびに絵・わくの位置から測るので、`layout()` の後に `#fx` の位置がずれて見えると、全部が同じだけずれる。Playwright で「`#fx` をずらして layout に測らせ、戻す」と、録画と同じ見え方になった（`compare-84.png` の左）。iPhone でどの操作のときに位置がずれたかは確かめていない（推測：向きを変えた途中・画面の切りかえの途中に layout が走った）。
- **もう一つ（小さい）**：logic では運んだが前のありんこがまだ持ち上げていない角砂糖のマスを、後のありんこが通っていた（v55 の直し）。ありんこの中心が見えている角砂糖の上にいたコマは 0.02〜0.28%。予備の道（絵の外から手を伸ばす）は前から 0%。
- **直し方**：①運ぶたびに `#fx` の位置を測り直す ②道は logic と同じ格子・同じ出発で探し、同じ 1 はこびで後から運んだマスは通らない ③まだ持ち上げていない角砂糖のマスを通るなら、持ち上がるまで出発を待つ（運ぶありんこがいなければ先に消す）。

### 3.2 B：道のりでいちばん近い角砂糖から
- 決まり（約束 §1.5 の 0.）：外の枠つきの格子で、巣（下の枠のまん中）から外の枠と外のマスだけを歩いた歩数＋1 がいちばん短いふちの角砂糖。同じなら前の順（巣に近い → 下 → 左）。描画の `findRoute` と同じ格子・同じ出発なので、ありんこの道の長さ＝選んだ道のり。
- 作り方（速さ）：盤ごとに道のりの表と、色ごとのふちの角砂糖の山（小さい順のヒープ。鍵＝道のり×(W×H)＋順位）。運ぶたびに運んだマス（とつながった閉じた空き）から短くなった所だけ幅優先で直し、まわりの角砂糖の鍵を下げる。`findTarget` は山の先頭を見るだけ。表は前の局面から引き取り（写さない）、前の局面をもう一度使うとき（1手もどし・生成の別の手）は作り直す。
- 速さ（Node）：一番大きい面（37 面・3072 個）の解を最後まで再生 約 42ms → 約 24ms。生成のいちばん重い面は 10 面 57ms（ちょうせん 65ms。前のいちばん重い面は 157 面 42ms）。AL11・AL20 は合格（基準は下げていない）。
- 総当たり（毎はこび幅優先で求めた答え）と、1・3・13・37・84・120 面の解の再生 13009 はこびで一致（テスト AL23 にも入れた）。
