## 1. 決めたこと（N1〜N10。約束 §1.14 に書き写した）

| 番号 | 決め |
|---|---|
| N1 数えるもの | 「落ち着いてから押す」遊び方で、今の局面から全部運べる ちがう行き着き方。「押して落ち着いた局面の並び」で見分け、同じ局面へ行く 2 つの列は 1 つ。同じ局面は 1 回だけ開き、そこから先の数は覚えの値を足す（数は 100 で頭打ち） |
| N2 関数 | `makeCount(state, { limit, memo, path })`・`countSearch`・`countKnown`・`makeCountMemo`・`COUNT_CAP` 100・`COUNT_LIMIT` 1,500（logic.js の rescueSearch の後） |
| N3 数えきれなかったとき | 開いた局面が 1,500 に届いたら打ち切り。見つけた数 1 以上なら `some`（「N いじょう」）、0 なら `unknown`（「わからない」）。100 に届いたら `many`（「100 いじょう」）。1,500 にした理由：§0 の 605 局面で とける局面の 99% は 130 局面までに答えが出て、500 を超えたのは 1 局面だけ。80 面の 1 手目の まちがいのように 2,500 でも出ない局面は、上限を上げても出ない（CPU 6 倍遅くの電話で 1,500 局面 ≒ 6 秒の見込み） |
| N4 覚え | `countMemo`（Map）。調べ終えた局面はちょうどの数、打ち切り・頭打ちで積んでいた局面は「見つけた数 いじょう」。とける 1 つめの手（c）も覚え、次の調べで先に試す。同じ面（面・絵・ちょうせん・setState）の間だけ。保存しない |
| N5 道しるべ | 押した手が `info.solution` の頭と同じなら続きを `path` に（§0 の 60・102・138・212 面のため）。試す順だけで、数は変えない |
| N6 数え始め | 局面が変わるたび（押す・1手もどす・もどす・やりなおし・面を始める・開き直す・setState）。運んでいる途中でも落ち着く先の局面を数える（「落ち着くたびに数え始め」より早い。落ち着いたときには たいてい出ている）。また変わったら取りやめ |
| N7 表示 | 絵の箱の下の行（巣の左右）。左「とける みち」・右に数。ちょうど 0 は「この ままだと ／ とけないよ」。0.25 秒より長くかかったら「かぞえてるよ…」。クリアの間は出さない |
| N8 予備軍 | 箱を押したあとの局面が ちょうど 0 のときだけ（`DOOM_LIMIT` の makeRescue はやめた）。わからない・N いじょう では知らせない。カードの言葉は今までどおり言い切らない（運んでいる途中に押すと助かる局面がまれにあるため。約束 §1.13 R3） |
| N9 もどす先 | `makeRewind(states, { base0Sure, memo })`：先に覚えを新しい方から引いて「1 とおり いじょう」の いちばん新しい k（床）を見つけ、床より新しい局面のうち覚えていない局面だけ今までどおり調べる。床より前へは戻らない |
| N10 重さ | 区切りを 1 回 8ms（前は 12ms）か 40 歩まで。数える `run(n)` は「局面を落ち着かせる回数」で区切る（覚えにある局面は開かないが落ち着かせる手間はかかるため）。目安：1 回の長い処理 50ms 以内（§5） |

- 「この ままだと とけないよ」は PM の言葉どおり（ちょうど 0 と言い切れたときだけ出す）。ただし判定は「落ち着いてから押す」遊び方の中の言い切りで、運んでいる途中に押すと助かる局面がまれにある（約 6%。§1.13 R3）。予備軍のカードは「かも」のまま。以下は私の推測：表示の「この ままだと」が その前提を やわらげているので、このままでよい。
