## 1. できあがりの形（2 本立て）

| | もよう（自動生成） | 写真・絵画から作る絵 |
|---|---|---|
| 数 | かぎりなし（面の番号から作る） | 約 100 枚（49 枚目から） |
| データ | **ほぼ 0**（作る台本だけ。約 5〜10 KB） | 約 70〜100 KB（送るときは gzip で約 11〜16 KB） |
| 権利 | 心配なし | PD・CC0 の元絵だけ（§4） |
| 元絵を取る通信 | 要らない | **要る**（今の環境では止められている。§5） |
| 楽しさ | 色と形のきれいさ・きもちよさ | 「何の絵かな」が分かる楽しさ |
| すぐ作れるか | **すぐ作れる** | 通信の設定と試作の結果しだい |

- 面の並び（おすすめ）：1〜48 面は約束の手描き。49 面から先は「足した絵（写真・絵画由来）」と「もよう」を混ぜる（例：絵 1 枚 → もよう 1 枚 の交互。絵が尽きたら もようだけ）。約束 §2.7 の「くり返し（左右反転）」は、もようが かぎりなく続くので **使わなくなる**（約束を直す）。
- 順番：**ゲーム本体（手描き 48 枚）を先に作って公開** → 次に **もよう** → 最後に **写真・絵画の絵**（試作で良いと分かってから）。理由：本体で絵の大きさ・色の決まりが正しいと分かってから足すほうが作り直しが少ない。もようは通信も権利も要らないので先に出せる。

## 2. もよう（幾何学模様）の自動生成

### 2.1 決まり
- **面の番号から毎回同じもようを作る**（種＝面の番号。乱数は種つき）。起動のたびに変わると、「途中から続ける」「1手もどす」「ずかん」で同じ絵が出ないため。作るのは**その面を始めるとき**（全部を起動時に作らない。1 枚 数 ms）。
- 文字の地図と同じ形（`.` と 10 色の文字）を作り、手描きの絵と同じ決まり（約束 §2.6 の 1〜5：大きさ・色の数と角砂糖の数が段の範囲・各色 3 個以上・閉じた空きなし）を**必ず満たす**。満たさなければ種を 1 つずらして作り直す（上限 20 回。だめなら決まった予備のもよう）。
- 同じ色のかたまりは 3 マス以上（小さすぎる箱を作らない。技術レビュー 3）。

### 2.2 もようの種類（最初は 8 種類。どれも左右か上下か回転の対称にして「きれい」に見せる）
1. まんげきょう（4 方向・8 方向の対称にでたらめの点を写す）
2. どうしんえん（まるの輪を内側へ重ねる）
3. ひしがた（ダイヤを重ねる）
4. しまもよう（ななめ・たて・よこ）
5. なみ（波の帯）
6. いちまつ（大きな市松）
7. ほし・はな（中心から花びら・星の先）
8. うずまき
- 内側の輪・中心の色が「閉じこめられた色」になるので、出す順番に意味が出る（遊びが面白くなる）。
- ずかんの名前は「もよう 1」「まんげきょう 12」のように種類と番号。ずかんは「え」と「もよう」に分ける（もようは数が増え続けるので、ずかんは「あつめた数」と最近の 20 枚だけを見せる）。

### 2.3 担当とテスト
- 作る：Opus（決まりを満たしながら きれいに見せる判断が要る）。ファイル `games/amai/patterns.js`（新規。DOM なし。Node で動く）。
- テスト（AL15 新設）：1〜2000 面のもようが全部、決まり 1〜5 と「かたまり 3 マス以上」を満たす。同じ面の番号で同じもようになる。1 枚 50ms 以内（iPhone SE 第 2 世代の目安。Node で 10ms 以内）。全部 `createLevel` で予備を使わず解ける面になる。変異：種を使わない（毎回変わる）・対称を崩す・かたまりの決まりを外す。
- 見本：8 種類 × 段 3 つの見本の一枚絵を PM が見て、ユーザーにも見せる。

## 3. 写真・絵画から作る絵（約 100 枚）

### 3.1 段の割り当てと順番（技術 4・UX 4）
- 49 面から先は手描きの XXL のあと。急にやさしくならないよう、**L 30・XL 35・XXL 35 枚**に割り当てる。並びは「XL と XXL を中心に、ときどき L（短い面で休む）」の波にする（UX 9：1 面 60〜100 秒が続くと疲れるため）。
- 季節の札：春・夏・秋・冬 各 10 前後、残りは通年。

### 3.2 試作のゲート（UX 2。100 枚に進む前に必ず）
- 5 題材で、(a) 台本だけ、(b) 台本＋手直し、(c) 手描き、の 3 通りを作って並べる。
- 判定（UX 1）：**名前を隠して見せて、何の絵か当てられるか**（PM とユーザー）。(a)(b) が (c) より明らかに悪い・手間が変わらないなら、写真・絵画の道は**やめて手描き（元絵なし）か もように切り替える**。

### 3.3 題材の選び方（UX 5・6、権利 5）
- 子どもに分かる身近なもの。形がはっきりしたもの（実物より記号に近いもの）。
- 避けるもの：怖いもの（へび・おばけ・虫の写真）、宗教・政治・戦争・国旗・お酒・たばこ・血、人の顔、**商品名・ロゴ・包み・特定の商品と分かる形**（お菓子は一般的な形：ショートケーキ・だんご・プリンなど）、キャラクター・他社のゲームの絵に似た形。
- 絵画は、そのまま題材になる静物・風景（花・果物・船・山・波）の数枚だけ。ほかは写真。
- 色覚（UX 8）：あか・みどり・ちゃいろの違いだけで分かる題材は避け、形で分かるものを選ぶ。
- 題材の一覧に「id（英小文字・数字なし）・名前（ひらがな・カタカナ）・段・使う色・季節・元絵の種類」を書き、**ユーザーの承認をもらう**（ユーザーの確認は「一覧」「最初の 10 枚」「全体」の 3 回に絞る）。

### 3.4 変換の台本（技術 5・8）
- `tools/amai-pixel.py`（Python・Pillow。作業環境にある）。リポジトリに入れるが、配信物（`APP_FILES`）には入れない。
- 手順：切り出し（絵ごとに範囲を記録）→ 背景を抜く（写真は四隅の色。絵画は範囲で指定）→ **大きいまま約束の 10 色に合わせる**（見た目に近い色の測り方 Lab。灰色・肌色などをどの色に寄せるかは表で決める）→ 多数決で縮める → 角砂糖の数が段の範囲に入るまで大きさを探す → 同じ色のかたまりを 3 マス以上に → 閉じた空きを埋める → むだな行・列を削る。
- 記録 `tools/amai-recipes.json`：元絵の URL・切り出しの範囲・使った数値。元絵を消しても、同じ手順で作り直せる。
- 手直しは **1 枚 1 ファイル**の文字の地図（`tools/amai-art/<id>.txt`）で行い、組み立ての台本で `pictures-c.js`・`pictures-d.js` を書き出す（大きな JS を手で直さない）。確かめは `logic.js` の決まりの関数を呼ぶ（決まりを二重に書かない）。
- 「手軽に増やす」＝ 次から「元絵 → 台本 → 手直し → 組み立て」の 4 手で 1 枚足せる。

## 4. 元絵の権利（権利レビューを反映。いちばん大事）

### 4.1 使ってよい元絵
- **商用・ゲーム集サイトへの掲載・広告ありでも使える元絵だけ**（事業化の計画〔docs/business-plan.md〕に広告ありの道があるため）。
- 出どころの順：
  1. **美術館のオープンアクセスの API**（権利の欄がある）：メトロポリタン美術館（`isPublicDomain: true` だけ）、米国ナショナル・ギャラリー（オープンアクセスの画像）、シカゴ美術館（`is_public_domain: true` だけ）、クリーブランド美術館・スミソニアン（CC0）。
  2. ウィキメディア・コモンズは、「美術館の画像を写したもの（元の美術館の URL がある）」か「PD-old-70 と作者の没年の記載がある平らな絵画」だけ。コモンズの「自分で撮った・CC0」の写真は使わない（札は誰でも書けるため）。
  3. ユーザーが自分で撮った写真（人の顔・ロゴ・商品の包み・他人の作品が写っていないもの）。
- **日本でも権利が切れているか**：作者の**没年が 1946 年以前**の作品だけ（死後 70 年・戦時加算の分に余裕をもたせる）。没年が分からない作品は使わない。立体（彫刻・器）は美術館が CC0 と明示した画像だけ。
- 確かめ先：文化庁「著作物等の保護期間」、著作権情報センター（CRIC）、各美術館のオープンアクセスのページ。迷う作品は使わない。

### 4.2 使わないもの
- **いらすとや**：無料で使えるが「著作権フリー」ではない（作者が権利を持ち、利用規約に条件がある。以下は記憶による推測：商用は 1 つの作品に 20 点まで）。今回は約 100 枚なので、条件を超える。ユーザーが規約を読んで決めたときだけ別に考える。
- 「フリー素材」としか書いていないもの、CC BY・CC BY-SA、Unsplash・Pexels・Pixabay（CC0 ではなく各サイトの独自の規約）、商標・キャラクター、人の顔の写真、他社のゲームの絵。
- **縮めても権利は消えない**。だから元絵の時点で上の 4.1 に限る。

### 4.3 記録（`docs/amai-credits.md`）とエージェントの決まり
- 欄：絵の id、元絵のページの URL（コモンズは版の固定リンク）、画像ファイルの URL、題名、作者、**作者の没年**、美術館の作品番号、**権利の根拠（API の欄の名前と値をそのまま写す）**、画像の指紋（SHA-256）、取った日、確かめた人と日。
- エージェントは**権利の欄を記憶から書かない**。実際に取った API の返事・ページの文字から写す。PM は 10 枚ごとに URL を開いて照らし合わせる。
- ゲームの中には出さない（CC0・PD は義務がない。出すなら画面・データ・テストの作業が別に要る。技術 7）。元絵の画像はリポジトリに入れず、作り終えたら消す（指紋と根拠は記録に残る）。

## 5. 通信（事実）

- この作業環境から `commons.wikimedia.org`・`api.openverse.org`・`collectionapi.metmuseum.org` などへつなぐと、作業環境の通信の決まりで断られる（2026-10-27。通信の見張りの記録に「gateway answered 403 to CONNECT」）。
- 元絵を取るには、ユーザーが環境の設定で通信を許す：セッションの上の環境メニュー → Edit → Network access の「Allowed domains」に、使う所だけを足す（例：`collectionapi.metmuseum.org`・`images.metmuseum.org`・`api.artic.edu`・`www.artic.edu`・`api.nga.gov`・`commons.wikimedia.org`・`upload.wikimedia.org`）。手順：https://code.claude.com/docs/en/cloud-environments#network-access
- 通信を許さないときは、ユーザーが §4.1 の 3 の写真か、美術館の CC0 のページから取った画像をアップロードする（出どころの URL を一言そえる。書いていない画像は変換しない）。

## 6. データの大きさ（技術レビューで測り直した。事実）

| 項目 | 大きさ |

| 写真・絵画の絵 100 枚（L〜XXL を混ぜたとき） | ファイル 約 81 KB、gzip 約 13 KB（全部 XXL でも 101 KB・16 KB） |

- 版を上げると、使っている人は事前キャッシュを 1 回取り直す（約 2.5 MB。今までの版上げと同じ）。圧縮（ランレングスなど）は要らない（300 枚を超えたら考える）。
