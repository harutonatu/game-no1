# テストの揺れを片付ける

- 作成：2026-11-06（PM・Opus）。状態：**作る段**。
- ユーザーの選択（そのまま）：「テストの揺れを片付ける (Recommended)」（説明：公開のたびに、今回触っていないゲームの性能・時間のテスト〔もくもくこうば WW10・WW2、ほしくだき KL19 など〕がときどき落ちて流し直している。「性能のテストは 3 回どれかで合格なら合格」などの決め方を入れ、公開を速く確かにする）。
- 今までの決め：落ちた（CRASHED）・止まった（STALLED）項目だけ 1 回流し直す（tests/run.mjs `MAX_RETRY = 1`。ユーザー決定 2026-10-25「1回のまま」）。

## 1. 決めたこと（PM 案）
### 1.1 揺れやすい項目の流し直し（run.mjs）
- テストの項目に「**揺れやすい**」の印を付けられるようにする（性能・時間・実時間に頼る項目。例：WW10・KL19・AL11・AL20・AW33・P9・S2・WW2・WW8・WW29・RL1・T-31 の HW18・HW8・HW17・BW2 など。どれに付けるかは担当が tests/design.md の「実時間で測る箇所」と課題表 T-31〜T-39 から選び、理由を 1 行ずつ書く）。
- 揺れやすい項目が**ふつうの不合格**になったら、全部の項目が終わったあとに、その項目だけを **1 つずつ順に（並列なし）最大 2 回**流し直す。どれか 1 回合格なら「**揺れ（流し直しで合格）**」として合格に数え、結果の最後に一覧で出す（隠さない）。2 回とも不合格なら不合格。
- 揺れやすい印の無い項目は、今までどおり流し直さない（本当の不具合を隠さないため）。落ちた・止まったときの 1 回の流し直しは今のまま。
- 公開の条件（CLAUDE.md §5）の文に、この決めを書き足す。
### 1.2 WW10（もくもくこうば 性能）
- 単独で流しても毎回落ちる（v59〜v63：34ms を超えるコマ 15.9〜60.9%、基準 10%）ので、流し直しでは片付かない。**原因を調べて、描画を軽くする**のが筋（課題 T-34 の案 (c)）。軽くできなければ止まって報告（基準を変えるかはユーザーと決める）。
- ほかのゲームも同じ形の性能のテストで、クラウドで落ちるものがないか確かめる（横展開）。
