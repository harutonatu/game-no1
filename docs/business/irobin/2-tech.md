# いろびん 技術レビュー（広く出す作品として）

確かめたこと：コードを読む（logic.js・main.js・render.js・index.html）／Node で 1〜300 面を生成して測る／Playwright（Chromium）で 8 種類の画面の大きさを開く／いろびんだけを別のフォルダに置いて開く／壊れた保存 7 種／既存のテスト BW1〜20・BL1〜14（full）。測った台本は scratchpad/irobin/t2/ にあります。

## 1. コードの誤り・表示・オフライン・保存

事実に基づいて：
- 既存のテストは 35/35 項目・308/308 確認がすべて合格しました（Chromium full、所要 67 秒）。
- 画面の大きさ 8 種（SE 縦 375×667・SE 横・320 幅・Pro Max 縦横・iPad 縦横・PC 1440×900）× 面 1・8・25・40・41 で、はみ出し・スクロール・44px 未満のボタン・ヒントのあふれは 0、コンソールのエラーも 0 でした。いちばん小さい瓶は 320 幅の 11 本で 45×108px です。
- 壊れた保存（`{`・`null`・`[]`・level が文字・1e400・存在しない瓶の手・最大の整数）はどれも落ちずに面 1（または保存の面の最初）から始まりました。
- 外への通信は 0 件（同じサーバー以外への要求なし）。
- 新しく見つけた低い不具合 1 件：**面を飛ばして切り替えると、お客さんの動物が前の面のまま残る**ことがあります。render.js 761 行は「枠の色が変わったか」だけを見て動物を描き直すため、前の面と同じ色の注文が同じ枠に来ると、動物（render.js 722 行の `c.kind`）が古いままです（41 面を 40 面のあとに開くと、ひつじのはずの客がねこ＝2人ともねこ）。ふつうの遊び方（クリア→次の面）ではクリアの時に枠が空になるので起きにくく、起きるのは setLevel（テスト・デバッグ）での面の飛ばしです。直すなら build() で `c.kind` を空にするだけです（手間 小）。
- PC・iPad では瓶が 76×182px で頭打ちになり、画面の下半分が空きます（崩れではない。見た目の損）。
- 既知：IB-08・09・10・11・12・13・16・17・19・21・22・24・25・29・30。

## 2. 面の生成の質（ここがいちばん大事）

事実に基づいて（1〜300 面、Node で測定）：
- 詰む面・予備の面への切り替え（fallback）は 300 面で 0。ほぼ同じ面（色を入れ替えると同じ並び）も 0。
- 生成の重さ：1 面あたり最大 43ms・最大 25,022 局面（この PC）。以下は推測です：SE でも 0.2 秒前後で、問題になりません（IB-12 の心配は実際の面では小さい）。
- **難しさは 40 面で止まり、そこから先は上がりません。** 面の表（logic.js 61〜72 行）は 40 面以降すべて「9 色・空き瓶 2・全部隠れ・布は偶数面だけ」です。測った数でも、でたらめに注ぐだけの人の勝率は 25〜39 面 17%、40〜99 面 12%、100〜300 面 13% と平らです。
- **面ごとのばらつきが大きく、奇数面が易しい。** 40〜199 面で、でたらめな人の勝率は奇数面（布なし）22%、偶数面（布あり）5%。20 回中 19 回でたらめで勝てる面もあれば、0 回の面（160 面中 66 面）もあります。「易しい・難しい」が交互に来るので、上達の手応えが崩れます。
- 解き手（ソルバー）は多くの面を 70〜85 局面で解きます（ほとんど後戻りなし）。「めやすの手数」（main.js 409 行の星）はこの解き手の手順の長さで、最短ではありません。40〜80 面の 41 面中 12 面で、でたらめに試すだけでめやすより短い手順が見つかりました。★★★ が取りやすく、星が上達の証になりにくいです。
- 空き瓶を 1 本にする案は、今の作り方では 60/60 面が作れず予備に落ちました。布を 2〜3 本にする案も予備に落ちる面が多い（26/60・50/60）。**表の数字をいじるだけでは難しくできません。**

以下は推測です：IB-29（40 面から作業げー）の原因は、①40 面以降の表が同じ、②選ぶ基準が「解けるか」だけで「考えどころがあるか」を見ていない、の 2 つです。

## 3. 広く出すときに技術で困ること

**単独で配るとき（事実に基づいて）**：いろびんだけを別の場所に置いて開くと、遊べてクリアもできました。足りなくなるのは次のとおりです。
| 依存先 | 無いとどうなるか |
|---|---|
| common/sfx.js（746 行。全ゲームの音の表が入っている） | 音が鳴らない（落ちない）。いろびんの表（392 行〜）だけ切り出せば済む |
| common/debug.js | 何も起きない（無くてよい） |
| sw.js（`../../sw.js` を登録） | オフラインで開かない。いろびん用の小さな sw が要る |
| manifest.webmanifest・icons/ | 名前が「ゆびあそび」のまま。いろびん用が要る |
| 「← メニュー」（`../../`）・goMenu | 戻り先が無い。単独版では隠すか自分のページへ |
また、リンクを貼ったときの見出し（OGP の og:title・og:image）と meta description が、メニューにもいろびんにもありません。SNS で貼られても絵が出ません。

**字体・通信**：字体は端末の字体だけ（Hiragino → system-ui）。外部から読み込むものは無く、外への通信は 0 です。

**英語化**：画面の文言は index.html 14・main.js 43・render.js 34・logic.js 10（色の名前など）の約 100 か所に散らばっています。ひらがなの分かち書きを前提に字の大きさを調整している所（main.js の setHint）もあります。以下は推測です：文言を 1 つの表（`TEXT.ja` / `TEXT.en`）に集めるのに半日〜1 日。

**保存が消える心配**：以下は推測です（出典 https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/ ）：iPhone の Safari では、ホーム画面に追加していない場合、7 日間サイトを開かないと localStorage が消されることがあります。知らない人の多くは追加しないので、「1 週間ぶりに開いたら 1 面から」が起こり得ます。保存の中身は実質「面の番号」だけなので、守るのは安くできます。

**共有の余地**：面は面の番号から必ず同じものが作られます（logic.js seedFor）。なので「41 面」と伝えれば同じ面になり、リンクで同じ面に挑ませやすい作りです。今は URL の `?` を読む所がありません。結果の画像は、瓶が DOM（canvas でない）なので、画像にするなら描き直しが要ります。文字で共有するなら安いです。

**遊ばれた回数を測る場所の候補**（入れるかはユーザーが決める。外部送信になる）：
1. main.js boot()（開いた回数）
2. main.js onClear()（クリアした面の番号。どこで離れるかが分かる。いちばん役に立つ）
3. main.js goNext()／askRestart（続けたか・やり直したか）
1 か所の送る関数にまとめ、オフライン時は送らず捨てる形がよいです。

## 4. 選ばれる理由のための、技術的に安い改善案

ここからは思い付きです。

| 案 | 効き目 | 手間 |
|---|---|---|
| **A. 「考えどころ」で面を選ぶ**：今は 1 面 25,000 局面ほどしか使っておらず、予算 200,000 に余裕がある。候補を数個作り、でたらめな人の勝率が低い面（または解き手の後戻りが多い面）を選ぶ。40 面以降は面の番号に応じて基準を少しずつ上げる | 大 | 中 |
| B. 奇数面にも布を入れる（`clothsOn: "even"` を外す。ただし 9 色の面は今の作りで予備に落ちる面があるので、A と組みにする） | 中 | 小 |
| C. 共有ボタン：クリアのカードに「いろびん 41めん ★★★ 32かい」と URL（`?lv=41`）を `navigator.share` で送る。`?lv=` は保存を変えない「その面だけ遊ぶ」にする | 中 | 小 |
| D. つづきコード：面の番号を URL や短い文字で出し、保存が消えても戻れる | 中 | 小 |
| E. OGP・説明文・いろびん用のアイコン | 中 | 小 |
| F. めやすを短くする：生成時に解き手の手順を後から短くする（同じ局面に戻る手を削る）か、短い手順を探し直す | 小〜中 | 小 |
| G. 単独版の用意（sfx の切り出し・小さな sw・manifest） | 遊ぶ場所が決まってから | 中 |

**おすすめは A** です。直接的な原因は「40 面以降の面の表が同じで、面の選び方が『解けるか』しか見ていない」こと、根本的な原因は「難しさを数で測る物差しが無い」ことです。直近は、今回使ったでたらめ勝率を物差しにして 40 面以降の面を選び直す（logic.js の tryParams だけ、変異テストはいろびんの分だけ）。中長期は、物差しで 1〜100 面の難しさの曲線を描き、表を決める作業を数字で回せるようにします。なお、面が変わると今の途中の保存（v:3）は手が合わなくなるので、保存の版を上げて「面の番号だけ残す」扱いが要ります（今の v:2 の扱いと同じ）。

## PMへの要点
1. 表示崩れ・エラー・外部通信は無し、既存テストは全合格。新しい不具合は「面を飛ばすと動物が前の面のまま」の低い 1 件だけ。
2. 難しさは 40 面で頭打ち（でたらめでも 12〜13% 勝てる）、しかも奇数面 22%・偶数面 5% と交互に揺れる。IB-29 の正体はこれ。表の数字だけでは直せない。
3. おすすめは「考えどころの物差しで面を選ぶ」（効き目 大・手間 中、logic.js だけ。保存の版上げが要る）。
4. 広く出す前に安く足せるもの：OGP・共有ボタン（`?lv=N`）・つづきコード（Safari の 7 日で保存が消える対策）。
5. 単独配布は sfx.js の切り出し・小さな sw・manifest・「メニュー」ボタンの扱いが要るが、遊ぶ場所が決まってからでよい。
